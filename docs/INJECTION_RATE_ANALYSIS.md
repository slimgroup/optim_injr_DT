# Injection Rate 不变的原因分析

## 观察

从图表 `comprehensive_threshold_sensitivity_sample=128.png` 和 `inj_rate_comparison_sample=128.png` 可以看到：

- **POF优化的注入速率**：在所有阈值（2.0-6.0 MPa）下都保持在约 **1.05**
- **CVaR优化的注入速率**：在所有阈值（2.0-6.0 MPa）下都保持在约 **1.05**
- **两者完全相同**，且不随阈值变化

## 可能的原因

### 1. 达到上界约束 ⭐ **最可能**

**证据**：
- 代码中有 `proj(x) = max.(x, 0)` 投影到非负
- 初始猜测 `inj_guess` 可能设置了上界
- 如果最优解总是触及上界，无论阈值如何变化，都会得到相同的注入速率

**验证方法**：
```julia
# 检查优化历史
# 查看 inj_rate_arr 是否在迭代过程中一直保持在某个值
# 查看梯度是否指向边界方向
```

### 2. 风险惩罚项权重太小

**原理**：
- 如果目标函数中，风险惩罚项（POF/CVaR）相对于基础目标（CO2注入量）权重很小
- 最优解主要由最大化CO2注入量决定
- 风险度量的选择（POF vs CVaR）影响很小

**检查**：
```julia
# 查看目标函数组成
# obj = obj_base + penalty
# 如果 penalty/obj_base << 1，说明风险项影响小
```

### 3. 阈值范围都在"安全区域"

**原理**：
- 如果所有阈值（2.0-6.0 MPa）下，风险水平都相对较低
- 可能都在"可接受"范围内
- 最优策略相似，都倾向于最大化注入

**验证**：
- 检查POF和CVaR的绝对值
- 如果都很小（如POF < 0.3, CVaR < 0.8），可能都在安全区域

### 4. 优化收敛到相同的局部最优

**原理**：
- 如果优化问题的landscape有多个局部最优
- POF和CVaR优化可能都收敛到同一个局部最优
- 这个最优解恰好对两种风险度量都适用

**验证**：
- 检查优化历史，看是否从不同初始点收敛到相同点
- 检查梯度是否接近零（是否真的最优）

## 代码中的相关部分

### 投影函数
```julia
proj(x) = max.(x, 0)  # 只保证非负，没有上界
```

### 初始猜测
```julia
inj_guess = args["inj_guess"]  # 通常设置为某个值（如1.05）
```

### 目标函数
```julia
obj = obj_base + penalty
# obj_base: CO2注入量（负值，因为要最大化）
# penalty: 风险惩罚项
```

## 建议

### 如果确实是上界约束：

1. **检查是否有隐式上界**
   - 查看 `inj_guess` 是否被用作上界
   - 检查是否有其他约束

2. **调整优化参数**
   - 增加风险惩罚项的权重（`lambda_pof`, `lambda_cvar`）
   - 使用硬约束而不是软惩罚

3. **扩大阈值范围**
   - 尝试更严格的阈值，看注入速率是否变化

### 如果风险项权重太小：

1. **增加权重**
   ```bash
   --lambda_pof 1e7  # 从1e6增加到1e7
   --lambda_cvar 1e7
   ```

2. **使用硬约束**
   ```bash
   --pof_as_constraint
   --cvar_as_constraint
   ```

## 对比较分析的影响

即使注入速率不变，POF和CVaR的比较仍然有意义：

1. **风险度量本身的差异**：CVaR/POF比率仍然显示CVaR更保守
2. **对阈值变化的敏感性**：相对变化率仍然显示CVaR更敏感
3. **数值差异**：CVaR的绝对值仍然比POF大

**结论**：注入速率不变不影响POF vs CVaR的比较，反而说明在这个问题设置下，风险度量的选择主要影响风险评估，而不是最优策略。
